# 事件驱动 USD/CNY 研究：预注册规则

## 0. 这份文件是干什么的

这份文件在**看到任何收益结果之前**写完并提交。它把标的、事件类目、方向规则、时间窗口、样本划分和验收标准全部钉死。

之后所有的回测结果都必须在这份规则不变的前提下产生。规则要改，就新开一份 v2 并说明改动理由，旧结果一并作废。

**唯一的可审计防线是 git 历史：这份规则的 commit 必须早于任何结果文件的 commit。**

原因很直接：外汇上"先看行情、再挑新闻解释"太容易了。同一天美元涨，可以说是"联储偏鹰"，也可以说是"避险情绪"；美元跌，可以说是"降息预期"，也可以说是"风险偏好回升"。事后叙事的命中率是 100%，信息量是 0。

## 1. 要回答的问题

> 一条已经公开的宏观新闻，在**发布之后**，对 USD/CNY 的下一段走势，是否还有超出随机的方向信息？

这是一个**弱预测**问题，不是一个"预测汇率"的问题。及格线不是高准确率，是"稳定地略好于抛硬币，且样本外不消失"。

### 不回答的问题

- 不预测汇率点位。
- 不做汇率投机方向的建议。
- 不解释历史（"2022 年 4 月为什么涨 4.24%"这类问题一律不回答，它没有可证伪性）。
- 不评价新闻本身对错。

## 2. 标的与权威数据源

单一权威源：**FRED / 美联储 H.10**。不混用其他汇率源，避免口径和 revision 差异。

| 序列 | FRED ID | 含义 | 方向约定 |
| --- | --- | --- | --- |
| 主标的 | `DEXCHUS` | 人民币兑 1 美元（在岸，纽约口径） | 数值上升 = 人民币走弱 = USD/CNY 上行 |
| 对照标的 | `DEXJPUS` | 日元兑 1 美元 | 数值上升 = 日元走弱 |
| 美元强弱 | `DTWEXBGS` | 美联储广义美元指数 | 上升 = 美元走强 |
| 美债短端 | `DGS2` | 2 年期美债收益率 | 上升 = 美国利率预期上行 |
| 美债长端 | `DGS10` | 10 年期美债收益率 | 备中美利差用 |
| 风险偏好 | `VIXCLS` | VIX | 上升 = 避险 |

收益一律用对数收益：`r = ln(P_t / P_{t-1})`。

### 已知缺口（本阶段不补，但必须在报告里明说）

- **无 CNH**（离岸人民币）。FRED 没有。CNH-CNY 价差是判断结售汇压力方向的关键变量，缺它会削弱识别能力。
- **无中国国债收益率日频**。中美利差只能等价用 `DGS10` 单边变动近似，这是个明确的简化。
- **无日内数据**。见第 7 节。
- **无中间价**。人民币中间价相对模型的偏离（逆周期因子）是境内定价的核心，本阶段完全缺失。

## 3. 时间口径与事件日归属（冻结）

三条规则，不允许在看结果之后调整：

1. **用新闻的原始发布时间，不用群转发时间。** 群消息里的早报会转发前一晚甚至前一天的新闻。转发时间当作事件时间会系统性地把事件推后，制造虚假的"新闻领先行情"。原始发布时间无法从正文确定的条目，**丢弃**，不做猜测填补。

2. **事件日按纽约时间归属。** `DEXCHUS` 是纽约中午买入价（NY noon buying rate），北京时间约为次日 00:00。归属规则：

   ```
   把新闻发布时间转换为 America/New_York 本地时间
   若该时刻 <= 当日 12:00  → 事件日 D = 该纽约日期
   若该时刻 >  当日 12:00  → 事件日 D = 下一个纽约日期
   再把 D 前滚到 DEXCHUS 序列中实际有报价的最近一天（跳过节假日）
   ```

   直觉检查：北京时间 D 日 09:00 的新闻 = 纽约 D-1 日 21:00 → 事件日 D-1？**不对**，需要注意跨日：北京 D 09:00 对应纽约 D-1 21:00，晚于 D-1 的中午，因此事件日 = D。北京 D 日 20:30（美国数据常见发布时间）对应纽约 D 08:30，早于 D 中午，事件日 = D。两者归到同一天，符合直觉。

3. **跨时区一律显式带时区**，不允许用裸 naive datetime 做比较。

## 4. 事件类目（封闭列表）

只有这 6 类。不在列表里的新闻标记为 `other` 并**排除出统计**，不允许临时增补类目来救结果。

| 代码 | 类目 | 典型触发内容 |
| --- | --- | --- |
| `US_MON` | 美国货币政策 | FOMC 决议、点阵图、联储官员讲话、纪要 |
| `US_DATA` | 美国经济数据 | CPI、非农、PCE、零售、PMI、GDP |
| `CN_POL` | 中国政策 | 降准降息、MLF/LPR、财政刺激、地产政策、政治局会议 |
| `CN_DATA` | 中国经济数据 | 中国 CPI/PPI、社融、进出口、GDP、PMI |
| `TRADE` | 中美贸易与地缘 | 关税、出口管制、实体清单、元首会晤、地缘冲突 |
| `FX_POL` | 汇率政策直接干预 | 逆周期因子、外汇存款准备金率、离岸央票、口头指导 |

分类由**规则表 + 人工抽检**产生，不用 LLM 批量分类。先手工标注 100 条建立基线；只有在基线证明信息量存在之后，才考虑上模型。

理由：现有宽关键词分类的方向命中率是 43%–53%，等于没有信息。在没有信息的标注上叠加模型，只会把噪声包装得更精致。

## 5. "意外"的定义（冻结）

新闻本身不带方向信息——发布即已被定价。有信息的是**相对预期的偏离**。我们没有 consensus 预测数据，因此用**因果分段**的市场反应作为意外的代理：

```
意外代理（在事件日 D 测量）：
  Δ2Y   = DGS2[D] - DGS2[D-1]        美国利率预期的变动
  ΔDXY  = ln(DTWEXBGS[D] / DTWEXBGS[D-1])   美元强弱的变动

响应（在 D+1 测量）：
  r1 = ln(DEXCHUS[D+1] / DEXCHUS[D])
```

**硬约束：意外和响应不允许在同一段时间内测量。** 用 D 日的美元变动去解释 D 日的 USD/CNY 变动是循环论证——它们本来就是同一个美元行情的两个投影，相关性高不代表有预测力。

因此主判据固定为 **r1**，它在事件日收盘后完全可交易。`r0` 只作为"市场确实有反应"的确认，**不进主判据**。

阈值（冻结）：`|Δ2Y| >= 3bp` 或 `|ΔDXY| >= 0.20%` 才算"产生了意外"，否则标记为 `no_surprise` 并排除。

### 缺观测的处理（冻结）

事件日或窗口端点上任一所需序列缺观测时，**该事件整条剔除，不做前值填补、不做插值**。

理由：填补会在"数据缺失"和"市场无变动"之间制造假的零变动，而零变动恰好落在 `no_surprise` 的判定边界上，会系统性地污染样本。

实测缺口（以 DEXCHUS 报价日历为主日历，研究窗口 2019-06-27 起共 1788 个报价日）：
`DGS2` 缺 4 天、`DTWEXBGS` 缺 1 天、`VIXCLS` 缺 7 天、`DEXJPUS` 缺 0 天。按最坏情况全部剔除，损失不超过 12 天，可以接受。

## 6. 方向规则表（冻结）

规则是**机械的**，输入只有类目和两个意外代理的符号。没有自由裁量项。

| 条件 | USD/CNY 方向偏置 |
| --- | --- |
| `US_MON` / `US_DATA` 且 Δ2Y > 0 且 ΔDXY > 0 | 上行（人民币走弱） |
| `US_MON` / `US_DATA` 且 Δ2Y < 0 且 ΔDXY < 0 | 下行 |
| `CN_POL` / `CN_DATA` 且 ΔDXY < 0 | 下行 |
| `CN_POL` / `CN_DATA` 且 ΔDXY > 0 | 上行 |
| `TRADE` 且 ΔDXY > 0 且 VIX 上行 | 上行 |
| `TRADE` 且 ΔDXY < 0 且 VIX 下行 | 下行 |
| `FX_POL` | 逆当前 20 日趋势方向（政策目标是抑制单边预期） |
| **两个意外代理符号冲突** | **无方向，不进统计** |

第 8 行是这套规则最重要的一条：**信号冲突时不强行给方向**。事后叙事之所以百发百中，就是因为它从不承认"这天说不清"。

明确禁止的做法：把"地产刺激""关税""政治表态"这类词直接映射成固定方向。同一个词在不同的增长预期、利差、风险溢价和资金流背景下方向相反。方向只能由上表的机械条件产生。

## 7. 窗口与重叠处理（冻结）

### 窗口

| 窗口 | 定义 | 角色 |
| --- | --- | --- |
| `r0` | `ln(P[D]/P[D-1])` | 反应确认，不进主判据（含部分同期信息） |
| `r1` | `ln(P[D+1]/P[D])` | **主判据**，事件日后完全可交易 |
| `r5` | `ln(P[D+5]/P[D])` | 持续性检验 |

**30 分钟 / 1 小时 / 当日日内窗口本阶段不做。** FRED 是日频单点，没有日内数据源；强行用日频数据近似日内窗口是伪精度。报告里这三个窗口一律标注"未测"，不给数字。

### 重叠处理

- 同一事件日出现多条同类目事件：**合并为一个事件**，方向取该日规则输出（规则输入是当日的市场变量，本来就唯一）。
- 同一事件日出现多个不同类目：若方向一致则保留，方向冲突则整日剔除。
- `r5` 窗口重叠导致的样本自相关：统计检验只用 `r1`（不重叠），`r5` 仅作描述性展示，不做显著性声明。

## 8. 样本划分（冻结）

| 用途 | 区间 | 规则 |
| --- | --- | --- |
| 训练/规则确认 | 2019-06-27 ~ 2024-12-31 | 允许查看，但规则已冻结，只是看命中率 |
| **样本外** | 2025-01-01 ~ 2026-08-21 | **只跑一次**。跑完即定论，不允许回头改规则再跑 |
| 安慰剂 | 全区间随机日期 | 随机抽取与事件数等量的非事件日，走同一套方向规则，重复 1000 次 |

价格数据止于 2026-08-21，之后的群消息不参与回测。

## 9. 验收标准（冻结）

样本外必须**同时**满足以下四条，才允许说"有信息价值"：

1. 样本外有效事件数 `n >= 30`
2. 样本外 `r1` 方向命中率的单侧精确二项检验 `p <= 0.10`（沿用 `forecast/pipeline.py:classify_tier` 已有的检验口径）
3. 样本外命中率 >= 训练期命中率 - 5 个百分点（不能出现断崖式衰减）
4. 安慰剂分布中，随机日期命中率 >= 真实事件命中率的比例 `<= 10%`

**任何一条不满足，结论就是"无信息价值"，写成负结果登记，不再调参重跑。**

这一条是整个设计里最容易被违反的。调参重跑到通过为止，等价于把样本外变成第二个训练集。

## 10. 如果通过，怎么用到企业外汇管理

前提：企业的问题不是"猜涨跌赚钱"，而是"手上有一笔确定要收/付的外币，锁多少、什么时候锁"。这个问题的损失函数是**不对称**的：

- 该锁没锁，汇率反向走 → 真实的经营亏损，要向老板解释。
- 锁了但汇率其实有利 → 少赚，但预算内、可解释、可审计。

所以弱信号在这里仍然可能有价值，用法只有一个方向：

> **只降不升。** 信号只在"方向对企业有利 **且** 模型质量达标"时，允许**少锁一点**；方向不利或模型不可信时，一律按目标套保比例足额锁。信号永远不能被用来增加敞口、加杠杆、或做无对应业务的投机头寸。

这与仓库现有 `web_app.py:forecast_multiplier` 的设计完全一致（support 1.0×/0.5×，caution 1.0×/0.7×，reject 1.0×/1.0×）。事件信号接入时沿用同一张倍率表，并且**融合规则是取更保守的一侧**：事件信号可以把 Prophet 给出的折扣收回，但不能把折扣放大。

方向不利的定义（沿用现有口径）：

- 未来要收外币（结汇）且预测外币贬值
- 未来要付外币（购汇）且预测外币升值

企业侧的真实收益来自三处，都不是"预测准"：

1. **少锁的那部分省下的远期点差和保证金占用**——这是确定的成本节省，只要方向判断不是系统性错的就成立。
2. **决策留痕**：每一次锁汇比例的调整都有可回溯的规则依据，而不是"我觉得美元要涨"。财务和审计能接受的是前者。
3. **拒绝的能力**：模型明确报告 `reject` 时，系统落回足额套保，这本身就阻止了一次基于叙事的裸敞口决策。

## 11. 终止条件

出现以下任一情况，立即停止并登记负结果，不再投入：

- 可用事件数（去重、可定位原始发布时间、非 `other` 类目、非 `no_surprise`）在训练期不足 100 条。
- 样本外未通过第 9 节四条中的任何一条。
- 发现事件表中存在无法排除的前视偏差（例如原始发布时间实际来自事后整理的稿件）。

负结果同样是产出：它明确回答了"这套逻辑在这批数据上不成立"，并且阻止了下一次基于同样直觉的重复投入。
